## 1. 目标、边界与不做什么

**目标**：把 17 张设计图上的每个可交互元素，翻译成方法+路径级别的接口设计，作为初期规划的联调基线；每条接口都标注它对应的设计图，方便对着蓝湖核。

**做**：
- 命名与通用约定（前缀、资源命名、批量命令、分页筛选、文件上传下载、实时策略）
- **62 个接口**的完整树 + 逐接口设计（**30 核心 + 32 新增模块**；用途 / 入口 / 要点 / 对应设计图）
- 关键流程：导入会话、标签合并改名、curl 实时预览、批量操作
- 未设计页面的占位接口与待确认清单

**不做（本轮）**：
- **字段级设计**：请求/响应字段名、类型、必填、校验规则、示例报文一律不写，等接口结构过审后单独出
- 数据库表结构、索引、迁移脚本
- 管理端登录、用户、角色、权限点设计（只留占位）
- MCP 协议端点（`/mcp` 侧）的暴露细节
- 前端组件划分与状态管理

### 2.1 从设计稿原文推出的两个结构结论

1. **服务创建 / 编辑服务共用同一个表单** —— 服务创建页副标题原文「编辑的时候写作编辑服务」。因此创建与编辑是一组接口（`POST /services` 与 `GET/PUT /services/{id}`），不是两套。
2. **8 张参数面板不是 8 个页面，是「编辑工具」详情页的内部构成** —— 编辑工具外壳页中央明确写着「这个框里的东西我们另起画板来画」。因此：
   - 请求侧：路径参数 / 请求头 / Cookie / Query 参数 / 请求体（类型：None、Form Data、Json）
   - 响应侧：Json / XML / HTML / Plain Text / Blob（状态：成功、成功|失败）
   - 这些**不各自成接口**，统一由 `GET/PUT /tools/{toolId}` 承载。

## 3. 命名与通用约定

| 项 | 约定 |
| --- | --- |
| 前缀 | `/api/v1` |
| 资源命名 | 复数、小写、无下划线：`services` / `tags` / `tools` / `imports` |
| ID 占位 | `{serviceId}` / `{tagId}` / `{toolId}` / `{importId}`（路径段用小驼峰占位） |
| 单条 CRUD | `GET`（查）/`POST`（建）/`PUT`（改）/`PATCH`（局部改）/`DELETE`（删），路径为 `/资源` 与 `/资源/{id}` |
| 批量命令 | **统一 `POST /资源/batch/{动作}`**，待操作 id 集合走请求体（避免 `DELETE` 带 body；也让 4 个批量按钮一一对应接口） |
| 子资源 | 归属关系只嵌套一层：`/services/{serviceId}/imports` |
| 列表筛选与分页 | 列表接口统一支持筛选 + 分页；分页参数从 1 开始，默认每页 10 条（对齐设计稿「每页 10 条」） |
| 响应包装与错误码 | ✅ **A1 已定案**：响应码 = HTTP 状态码(3 位) + 2 位业务细分 = **5 位数字**；信封字段、错误码表与**分页形状**见 **3.1** |
| 时间格式 | ISO-8601 带时区偏移；仅日期用 `yyyy-MM-dd`（见 A12） |
| 文件上传 | 仅导入步骤① 使用 `multipart/form-data` |
| 文件下载 | 仅批量导出使用文件流响应 |
| 实时策略 | curl 预览走 **HTTP 主方案**（见 6.6.6），WS 作为预留升级点，接口语义与 HTTP 版一致 |
| 幂等期望 | 批量命令与导入 commit 需可安全重试（同一 `importId` 重复 commit 不产生重复工具） |
| **鉴权模式** | ✅ **A2 已定案（2026-10-15）**：`auth.mode = dev \| jwt`，**显式开关**。阶段 0 跑 `dev`（免鉴权，固定注入默认租户 + dev 用户）；**管理面永不因缺 JWT 降级**；`prod` + `dev` 组合**拒绝启动** → 详见 **4.1** |
| **敏感值掩码** | ✅ **A4 已定案（2026-10-15）**：`sensitive=true` 读接口一律返回 `***`；**写回 `***` = 保留原值**；审批详情对**所有人（含审批人）**掩码 → 清单与机制见 **3.2** |
| **版本与乐观锁** | ✅ **B2 已定案（2026-10-15）**：**服务 / 工具 / 标签 / 资源 / 提示词**的**详情响应返回 `version`**，**`PUT` 与删除请求必带 `version`**；不一致 → **`40901`**，响应 `data` 里回 **`current`**（服务端当前值，供前端展示"已被他人修改"）。**仅审批用 `baseVersion` 不够** —— `SIMPLE` 模式下并发编辑会静默覆盖。**分页列表不必带** `version`（点进详情才需要）。⚠️ **排除两类**：**`mcp_config`**（upsert 语义，唯一键 `uk_config` 不含 version，单管理员低频改）、**`mcp_user`**（改角色 / 停用属低频操作）—— 给它们套乐观锁**技术上别扭且无实际并发场景** |

### 3.1 统一响应体与错误码（✅ **A1 已定案**，2026-10-14）

**你给的规则**：响应体 = **响应码 + data**；响应码 = **HTTP 状态码（3 位）+ 2 位业务细分码 = 5 位数字**。

**三条假设已全部确认（不再是待确认项）**：

| # | 事项 | ✅ 定案 |
| --- | --- | --- |
| 1 | HTTP 状态码**是否镜像**前 3 位 | **镜像** —— `40001` 真回 HTTP `400`，`20000` 回 `200`（网关 / 监控 / 浏览器都保有标准语义） |
| 2 | 固定字段集 | `{ "code": 20000, "message": "OK", "data": …, "traceId": "…" }`；`data` 可为对象 / 数组 / `null` |
| 3 | 分页**位置** | **放 `data` 内**（顶层摊平的方案已排除） |

**分页形状已定案：采用 ✅ A 形状**（顶层摊平方案违背第 3 条，已出局）：

```jsonc
// ✅ A 形状（已采用 —— 通用命名）
{ "code": 20000, "message": "OK",
  "data": { "list": [], "total": 0, "page": 1, "pageSize": 10 },
  "traceId": "…" }

// C 形状（备选 —— MyBatis-Plus IPage 原生命名，若团队更在意"后端零转换"则一行切换）
{ "code": 20000, "message": "OK",
  "data": { "records": [], "total": 0, "size": 10, "current": 1, "pages": 0 },
  "traceId": "…" }
```

> **为什么最终选 A**：`list` / `page` / `pageSize` 语义直白、**不绑框架**（前端、Apifox 用例、跨语言客户端都无歧义）；C 的 `size` 容易被误读成"内容大小"、`pages` 是派生值。C 唯一优势是 `IPage` 直接序列化零转换 —— 代价只是 4 处列表接口的响应映射，**要换回 C 一行改**。

**码段草案**（前 3 位跟 HTTP，后 2 位细分）：

| 码 | HTTP | 含义 |
| --- | --- | --- |
| `20000` | 200 | 成功（通用） |
| `20001` | 200 | 成功但**部分失败** —— 4 个批量操作都会用到（见 5.3） |
| `40001` | 400 | 参数校验失败（字段级错误放 `data.errors[]`） |
| `40002` | 400 | **名称重复 / 唯一性冲突** —— ✅ **C2 定案**：**"查一次就能判定"的存在性冲突**（提交预校验即可发现：名称 / 租户 `code` / `username` / 标签名已被占用）→ 前端提示「**换个名字**」 |
| `40003` | 400 | 状态不允许（如对已启用服务重复启用） |
| `40100` | 401 | 未认证（Token 缺失 / 失效） |
| `40300` | 403 | 无权限（超出 Token 可见范围） |
| `40401` | 404 | 对象不存在 |
| `40901` | 409 | **并发 / 状态冲突** —— ✅ **C2 定案**：**"必须依赖 `version` 或 `status` 前置条件才能判定"的冲突**（乐观锁失配、审批单已被处理）→ 前端提示「**数据已变化，请刷新后重试**」 |
| **`42301`** | **423** | **账号已锁定**（✅ A5 定案 2026-10-15：连续 5 次失败锁 15 分钟）—— **必须与 `40100` 分开**，否则前端分不清"密码输错"和"请稍后再试" |
| `42901` | 429 | 限流 —— ⚠️ **C4 定案（2026-10-15）：本期「限流」与「配额」都不做** → **本码位保留、本期不使用（预留）** |
| `50001` | 500 | 服务内部错误 |
| `50002` | 502 | 上游接口不可达（调用期确认失败，见 MCP 文档 9.2） |

> ✅ **C2 定案（2026-10-15）：`40002` 与 `40901` 的边界规则**
>
> 此前同一类事在两处用了不同码（租户 `code` 撞车、`username` 唯一、审批 R2/R3 都写成 `40901`，而 `40002` 的定义是"名称重复"），**且数据库稿写过裸 `409`**。定案：
>
> - **`40002`（400）** = **存在性冲突** —— **查一次就能判定**（`SELECT ... WHERE name_norm = ?`），语义是「**你选的名字被占了**」；
> - **`40901`（409）** = **并发 / 状态冲突** —— **必须读 `version` 或 `status` 才能判定**，语义是「**你基于的数据已过期**」；
> - **数据库稿里的裸 `409` 一律改 `40901`**（不得只写 HTTP 码）；
> - 实现口径：**预校验失败 → `40002`；落库瞬间捕获唯一约束/乐观锁异常 → `40901`**。
>
> **改动点**：租户 `code` 撞车（5.9）→ `40002`；`username` 唯一（5.11）→ `40002`；审批 **R2/R3**（存在性检查）→ `40002`；**R5**（`baseVersion` 失配）**保持 `40901`**；5.5 标签改名撞车 → `40002`。

**例外条款（不套信封）**：

- **文件流下载 / 批量导出**：直接返回二进制流；
- 其余接口（含 `POST /tools/curl-preview`、导入 `multipart` 上传）**统一套信封**，保证前端拦截器只有一条路径。

### 3.2 敏感值清单与掩码机制（✅ **A4 已定案**，2026-10-15）

**判定规则（一句话）**：**这个值泄露后，攻击者能不能直接拿去访问上游、或冒充身份？** 能 → 敏感。所以 URL / 名称 / 描述 / 开关**不是**敏感；**凭据与密钥是**。

**敏感值全集（按落点）**：

| # | 落点 | 内容 | 处理 |
| --- | --- | --- | --- |
| 1 | `mcp_service_auth_param.value`（**固定值**） | 服务级鉴权参数（`COOKIE` / `HEADER` / `QUERY` / `BODY_*`） | **C3 + 缺口口径定案（2026-10-15）：本列已补上** —— 原表**只有 `sensitive` 列却没有 `value` 列**，掩码**无对象**；`sensitive` **默认 `true`** |
| 2 | 工具 `request_json` 参数对象里的 **`value`（固定值）**，以及 header / cookie / query 的**值** | 工具参数面板（#04 / #06）里填的 token / 固定值 | 同上，默认敏感 |
| 3 | `mcp_config` 中标 **`isSecret=true`** 的项 | **当前 6 个键全部为 `false`** —— 密钥类都在 env-only、不经 API，所以**现在没有需要掩码的配置项**；将来把密钥类搬进页面时**必须先标 `true`** | 见数据库稿 12.3 白名单标记 |
| 4 | `mcp_user.password_hash` | 密码哈希 | **任何响应都不返回**（不是掩码，是不给） |
| 5 | `mcp_client_token` 明文 | api-key | **只在创建响应里出现一次**；列表 / 详情只给 `token_prefix` |
| 6 | `mcp_operation_log.detail_json` | 调用明细 | **写入侧就过滤**（不记敏感值），读取侧再兜底 |
| 7 | 将来：租户 SSO `client_secret` | —— | 现在就按敏感处理 |
| **8** | **调用方在工具入参里传入的凭据**（⚠️ **C3 定案后新增的漏点**） | MCP 请求 `arguments` 里的凭据值（无固定值、或允许覆盖时由模型/客户端传入） | ⚠️ **绝不落任何日志** —— 写入侧就过滤：`mcp_operation_log.detail_json`、审计日志、**异常堆栈**、`curl` 预览、DEBUG 报文回显**一律不得包含**。**这是"库外漏点"，风险比库内更高**（我们连掩码的机会都没有） |

> ⚠️ **第 8 行是 C3 定案的连带要求**：既然凭据**默认由调用方在工具入参里传**（设计图 #13 的鉴权块带 `MCP 参数名` + `MCP 描述` 两列），那么**凭据值会流经我们的进程内存与日志**。清单第 1/2 行只覆盖"我们库里存的"，**第 8 行覆盖"路过我们的"** —— 两者都要按敏感处理。**验收标准**：任意一次带凭据的工具调用，其 `mcp_operation_log` 与全部日志文件中**不得出现该凭据原文**（可二值判定：`grep` 不到）。

**读写语义**：

- **读**：`sensitive=true` → 一律返回 `***`（前端据此显示"已配置"，仍可覆盖编辑）；
- **写**：传 `***` = **保留原值**（不覆盖）；传其它值 = 更新。（传空 / 缺字段是否等于清空，属字段级契约范围，见第 9 章）
- **审批**：申请详情里的敏感值**对所有人掩码，含审批人** —— 理由与替代验证方式见 **5.10.4**；
- **实现**：统一用 `@Sensitive` 注解 + Jackson 序列化器出参加码，**禁止各接口手写**（手写必漏）。

#### 4.1.1 阶段 0 的鉴权（✅ **A2 已定案**，2026-10-15）

**原来的真实冲突**：阶段 0 只做 30 个核心接口（**不含登录**）＋ **A13** 要求"除 login 外都要带凭据（**Bearer JWT 或 `HttpOnly` cookie**）"＋ 数据库稿 3.4 写「都取不到 → **默认租户**」→ **照字面实现 = 未认证请求落默认租户直接放行**（越权）。

**定案：阶段 0 明确免鉴权**，但必须按下面**四道护栏**落地，缺一不可（第 4 条是 2026-10-16 补的，见 §5 #18）。

| # | 护栏 | 为什么必须有 |
| --- | --- | --- |
| 1 | **显式开关，不是降级兜底** —— `auth.mode = dev \| jwt`。阶段 0 跑 `dev`：**固定**注入默认租户（`id=1`）+ 一个固定 dev 用户（角色 `ROOT`） | 开关决定的是**固定值**；"任何取不到就降级"是**兜底** —— 两者长得像、后果完全不同。**「管理面永不因缺 JWT 降级」这条结论保持不变** |
| 2 | **生产环境拒绝启动** —— `spring.profiles.active=prod` 且 `auth.mode=dev` → **启动直接失败**（不是 WARN） | 否则一次误配置就把"免鉴权控制台"发出去了 |
| 3 | **现在就留骨架** —— 加 `AuthFilter` 空实现，两个模式共用同一入口；阶段 1 只换 `jwt` 分支的实现 | 否则阶段 1 要回头给 30 个接口逐个补鉴权注解 |
| 4 | **`jwt` 模式下不只验签，还要验"人"**（✅ **2026-10-16 主人拍板**，见 §5.7.2 / 决策记录 §5 **#18**）—— 除签名 + `exp` 外，**必须校验该用户 `status = ACTIVE` 且未被删除**（`mcp_user.status` / `deleted_seq`），配 **60 秒短缓存**（键 = `userId`） | 无状态 JWT ＋ 无黑名单 ＋ **7 天**有效期 ⇒ 不查用户状态的话，**停用/删除用户后他还能进 7 天** —— **「停用用户」这个功能就是假的**（且与 api-key 禁用"立即 `40100`"不对称） |

**配套**（✅ **2026-10-19 扩充为 7 条**）：
1. 阶段 0 **不可对外部署** —— 该限制必须写进用户手册「限制」章节；
2. ✅ **`AuthFilter` 取 JWT 的来源 = 优先 `Cookie`（浏览器），兼容 `Authorization: Bearer`** —— 否则运维脚本 / Apifox / 自动化测试**无法调用**（同源 cookie 方案的必要补充）；
3. ✅ **`mcp_user.must_change_password = 1` 时只放行白名单**（`POST /auth/change-password`、`GET /auth/me`、`POST /auth/logout`），其余一律 **`40003`**（状态不允许）—— **否则"强制改密"是假的**。⚠️ **本批（阶段 0）无用户概念，该条属阶段 1**；
4. ✅ **宿主约定（2026-10-19 细化）：`docker-compose` 内置 nginx** ⇒ **对外是同一个域名**（前端静态 + `/api` / `/mcp` / `/sse` / `/messages` 全由 nginx 反代到后端）⇒ **无 CORS**。**「前后端不在同一 IP」由 nginx 的 `proxy_pass` 解决**（nginx 在 A 机、后端在 B 机，**对外仍是同源**）—— **不需要跨域支持**。🔴 反代必须同时对 `/sse` **关闭缓冲**（`proxy_buffering off;` / `X-Accel-Buffering: no`）**并把 `proxy_read_timeout` 调大**（默认 **60s** 会掐断长连接）—— 否则 `GET /sse` 会被缓冲/掐断成"永远收不到消息"（**M11**）；
5. 🔴 **反代必须透传 `Mcp-*` 头，且不得改写 `/mcp` 路径** —— `EraRouterServlet` **靠 `Mcp-Method` 头分流**（**D6**），三个 provider 靠 **`getRequestURI().endsWith("/mcp")`** 自检。若反代/安全网关**剥掉 `Mcp-Method`** ⇒ **所有请求全落形态二、形态三静默失效**（**D6 白解决**，现象一模一样）；若 `proxy_pass` **带路径**（如 `proxy_pass http://backend:8080/;`）会改写 URI ⇒ **provider 自检失败、全挂**。⇒ 配置要求：**`proxy_pass http://<backend>:8080;`（不带路径）** + **白名单透传 `Mcp-Method` / `Mcp-Session-Id` / `Mcp-Name` / `MCP-Protocol-Version`**；
6. 🔴 **`/mcp`、`/sse`、`/messages` 只认 api-key，必须显式忽略 Cookie 与 JWT** —— 同源后**浏览器访问 `/mcp` 会自动带上控制台 cookie**；若 `AuthFilter` 统一"优先 cookie"，**浏览器可用控制台身份直连 MCP 端点**，绕过 api-key 的**租户归属**与**即时撤销**语义（api-key 撤销 = 立刻 `40100`；cookie 最长 **7 天**）⇒ `AuthFilter` **按路径分流**：`/api/v1/**` → JWT（cookie ‖ Bearer）；`/mcp` / `/sse` / `/messages` → **只认 api-key**；
7. ⚠️ **`Secure` cookie 按 profile 推导，不新增配置键** —— `SPRING_PROFILES_ACTIVE` 含 `prod` → **`Secure=true`**；其他 → **`false`**（否则**本地 `http://localhost` 登录不上**，浏览器拒收 `Secure` cookie）。**不引入 `server.forward-headers-strategy`**：`Secure` 是我们自己写 `Set-Cookie` 时的**字面量**，**不依赖 `X-Forwarded-Proto`**；仅当将来需要"按原始 scheme 生成绝对重定向"时再加。
8. 🔴 **产物下载端点必须独立路径 + `AuthFilter` 显式放行** —— 本机存储时 M22 的"签名 URL"**由我们自己提供**：`GET /artifacts/{artifactId}?sig=…&exp=…`。三个硬约束：① **不能放在 `/api/v1/**` 下**（否则被 JWT 拦截 —— MCP 客户端拿 URL 直接 GET，**没有 cookie、没有 header**）；② **鉴权 = URL 签名本身**（签名体含 **`tenant_id`**，防猜 id 跨租户；**短 TTL 15 分钟**，见 `artifact.url_ttl_minutes`）；③ **nginx 要反代该前缀**且它**公网可达**。⚠️ 这条**不在 62 个管理面接口里**（它是 MCP 输出侧用的），别去管理面接口表找它。

- ⚠️ **校验与错误文案不在设计图里承载（✅ 2026-10-21 定案，决策 #25）**：工具名格式 / 简称长度 / 服务名唯一 / URL 前缀 / 导入格式与 ≤10MB / 测试失败态等 **14 项**，逐项归属与文案见 [`设计稿待办清单.md`](./设计稿待办清单.md) **§2**

### 5.4 导入接口（导入会话）

> 设计稿 4 步导航 ↔ 3 个接口。**步骤② 完全在前端**（改名 / 改路径 / 反选 / 删除 / 解除），不产生任何请求。

#### 5.4.1 上传并解析（步骤①）
- **方法与路径**：`POST /api/v1/services/{serviceId}/imports`
- **入口**：导入接口1「点击此区域或拖拽文件至此区域上传」
- **用途**：接收 OpenAPI / Swagger 文件，解析出候选接口清单，创建一次**导入会话**
- ✅ **C5 定案（2026-10-15）：格式与版本解耦** —— **`JSON` 与 `YAML` 都可承载 `Swagger 2.0` / `OpenAPI 3.0` / `3.1`**，**版本按内容探测**（看顶层 `swagger:` 还是 `openapi:`），**扩展名只作提示、不作判定依据**。原文「OpenAPI 3.0/3.1（Json）或 Swagger 2.0（Yaml）」把格式绑死到版本上是**契约矛盾**，已作废
- **要点**：文件限制见 A6；返回导入会话标识 + 候选清单（含设计稿列出的：名称、路径、方法、请求体有无、返回体有无、重复冲突、MCP 类型推断）；候选需带稳定标识，供步骤② 前端本地编辑时引用
- **对应设计图**：导入接口1

#### 5.4.2 执行导入（步骤③ → 步骤④）
- **方法与路径**：`POST /api/v1/services/{serviceId}/imports/{importId}/commit`
- **入口**：导入接口2「确认导入」
- **用途**：按步骤② 的前端改动执行入库，返回结果统计
- **要点**：
  - **只收变更集**（哪些候选被改名/改路径/改 MCP 类型、哪些被取消勾选），未提及的候选沿用步骤① 的解析结果；前端无需回传整份 OpenAPI 文档
  - 「冲突」的**最终判定权在服务端**：步骤① 返回的冲突标记仅供提示，前端自行清除标记后，若实际重名，仍在此接口以「未能导入」明细返回（不会脏写）
  - 结果统计按设计稿三层结构返回：成功导入总数（含其中「覆盖」子计数）、未能导入数（含失败原因）
  - 幂等：同一 `importId` 重复提交不得产生重复工具
- **对应设计图**：导入接口2、导入接口3

#### 5.4.3 放弃导入
- **方法与路径**：`DELETE /api/v1/services/{serviceId}/imports/{importId}`
- **入口**：无显式按钮（关闭页面 / 重新选文件时前端 best-effort 调用）
- **用途**：释放导入会话
- **要点**：服务端另加 **TTL 30 分钟**兜底回收（见 A20），因此该接口失败不影响正确性
- **对应设计图**：导入接口2

- **方法与路径**：`PUT /api/v1/tools/{toolId}`
- **入口**：编辑工具页「保存」
- **用途**：一次性保存整份工具定义
- **要点**：
  - **嵌套结构一次提交**，不是分块各自保存；路径参数不参与提交
  - 🔴 **`MCP 工具名` 必须服务端强校验（D2 定案 2026-10-15，SDK 真机实证）**：合法字符仅 `A-Za-z0-9` / `_` / `-` / `.`，长度 **1~128** → 正则 **`^[A-Za-z0-9_\-.]+$`**。**不合法 → `40001`**（参数校验失败，在 `data.errors[]` 里指明字段）。

    - ⚠️ **UI 提示**：**中文只能用于「模型可见的描述」列，不能用于 `MCP 工具名`**；前端**建议做同一正则的前置校验**，但**以服务端校验为准**（前端可被绕过）。
    - **验收用例**：提交 `MCP 工具名` = `中文工具` → 必须 **`40001`** 且 `data.errors[]` 指向该字段；提交长度 129 → 同样 `40001`。

#### 5.6.6 curl 预览
- **方法与路径**：`POST /api/v1/tools/curl-preview`

- **用途**：由**后端**根据当前编辑内容生成 curl 语句
- **要点（已定案）**：

  - 后端据此解析服务的 URL 前缀并注入服务级鉴权参数

  - **转义风格**：仅输出 POSIX sh 风格（对齐设计稿）；**鉴权参数敏感值掩码**（见 A21，两项都可在 A21 一行改回）
  - **WS 为预留升级点**：若后续实测出现可感知延迟，或 curl 需掺入服务端探针，再新增 `/tools/curl-preview/stream`，沿用同一套草稿与序号语义，前端仅换传输层，契约不变

#### 5.7.1 登录
- **方法与路径**：`POST /api/v1/auth/login`
- **入口**：登录页
- **用途**：`{ tenantCode, username, password }` → ✅ **2026-10-16 拍板（同源双容器）：JWT 不再放响应体**，改为 **`Set-Cookie`** 下发 —— `HttpOnly` + `Secure` + **`SameSite=Lax`** + `Path=/` + `Max-Age = auth.console_jwt_ttl_minutes`；响应体**只返回用户信息**（`userId` / `displayName` / `role` / `tenantId` / `tenantCode` / **`mustChangePassword`**）
- 🔴 **为什么用 `HttpOnly` cookie**：宿主约定「**前端与后端同源部署**（两个 Docker 容器，前端容器反代 `/api` 与 `/mcp` → 后端容器）」⇒ 无 CORS、可用 cookie；**`HttpOnly` 让 XSS 偷不到 token**（若用 `localStorage`，XSS = 最长 **7 天**持续越权，见 §5.7.2）
- **CSRF**：靠 **`SameSite=Lax`**（跨站 POST 带不上 cookie）+ 服务端**校验 `Origin` / `Referer`** 白名单；本期不引入 CSRF token（真需要再加）
- **要点**：**用户名只在租户内唯一** ⇒ 登录必须带 `tenantCode`（默认租户为 `default`）；失败**统一返回 `40100`**，不区分"用户不存在 / 密码错"（防账号枚举）；SSO 预留（A13）
- ✅ **已定案（2026-10-16，§5 #19 关闭）**：JWT 存 **`HttpOnly` + `Secure` + `SameSite=Lax` cookie**（理由见上一条）；**`localStorage` 方案作废**（XSS = 最长 7 天持续越权）。**收到 `40100` 的统一处理**：前端**清本地用户态 → 跳登录页**（token 在 cookie 里，由服务端过期/清空，前端不持有）
- **对应设计图**：无（新增模块）

#### 5.7.2 登出
- **方法与路径**：`POST /api/v1/auth/logout`
- **入口**：右上角用户菜单
- **要点**：✅ **2026-10-16 拍板（同源双容器改判）** —— 登出**必须由服务端清 cookie**（响应 `Set-Cookie` 同名 + `Max-Age=0`），**前端同时清本地用户态**；JWT 无状态仍**不维护黑名单**（"立刻踢下线"仍属预留；折中方案 = #18 的"**验人**"，**60 秒内生效**）
- **有效期（✅ 2026-10-16 主人拍板）**：**人登录按 7 天** —— `auth.console_jwt_ttl_minutes` = **`10080`** 分钟，**租户内可配、允许不配**（不配按生效链回落，见 [`数据库设计.md`](./数据库设计.md) **§12.3**）。⚠️ **无状态 JWT 不回溯**：改配置**只影响新签发**的 token，已签发的到**原 `exp`** 为止才失效（**改小也不提前踢人**）
- ✅ **已拍板（2026-10-16，[`设计决策记录.md`](./设计决策记录.md) §5 #18）：`AuthFilter` 在 `jwt` 模式下"不只验签，还要验人"** —— 除签名 + `exp` 外，**必须校验该用户 `status = ACTIVE` 且未被删除**（`mcp_user.status` / `deleted_seq`），配 **60 秒短缓存**（键 = `userId`）⇒ 停用 ≈ **60 秒内生效**，**不需要** token 黑名单
- **验收（可二值判定，三条）**：① **禁用**用户 A → A 手上的 JWT 在 **≤60 秒**内再请求 → **`40100`**（**不是 200**）；② **删除**用户 A → 同上；③ 用户 A **正常**时 → 请求 **200**（证明不是把所有请求一律拒掉）

#### 5.7.3 当前用户
- **方法与路径**：`GET /api/v1/auth/me`
- **入口**：前端路由守卫 / 页面初始化
- **用途**：返回用户 + 角色 + 租户 + **当前租户的权限模式** `access.change_mode`
- **要点**：前端**靠它决定"显示新增/编辑按钮"还是"显示提交申请按钮"**，避免前端自己猜权限
- **对应设计图**：无（新增模块）

#### 5.7.4 修改密码（自助）
- **方法与路径**：`POST /api/v1/auth/change-password`
- **入口**：右上角用户菜单 / 「**强制改密**」拦截页
- **用途**：`{ oldPassword, newPassword }` → `200`
- **要点**：✅ **2026-10-16 拍板 —— 它是 A 类 #1「强制改密」的必要承载**（没有它，`must_change_password` 标志**清不掉**）。校验旧密码；新密码**复用 A5 策略**（≥8 位且同时含字母与数字）；成功后**清 `must_change_password`** + **重新签发 cookie**（推荐，免打断；也可要求重新登录）；SSO 用户（`password_hash` 为空）返回 **`40003`**
- 🔴 **改密成功后必须主动失效 §5 待办 #18 的"60 秒用户状态缓存"**（键 = `userId`）—— 否则用户**改完密还要等最多 60 秒**才能访问其他接口（纯体验 bug，但很容易漏）
- ⚠️ **阶段归属**：本接口与「强制改密」**都在阶段 1** —— **第一批交付 = 阶段 0（30 个核心接口，无用户概念）**，故本批**不需要**；⚠️ **UI 承载缺页**（17 张设计图里没有"强制改密"页），见 [`设计决策记录.md`](./设计决策记录.md) §5 **#22**
- **对应设计图**：无（新增模块）

> ⚠️ **本接口使管理面接口总数 61 → 62**（§4 接口树 / 附录 A / README 同步）。

### 5.8 租户（阶段 1，**仅 ROOT**）

#### 5.8.1 租户列表
- **方法与路径**：`GET /api/v1/tenants`
- **要点**：分页 A 形状；支持 `keyword`（编码 / 名称）与 `status` 筛选；**非 ROOT 调用返回 `40300`**

#### 5.8.2 新建租户
- **方法与路径**：`POST /api/v1/tenants`
- **用途**：`{ code, name, adminUsername?, adminPassword?, expiresAt? }`
- **要点**：`code` 小写存储、全局唯一（撞车 → `40002` —— 存在性冲突，C2 定案）；**建议同时创建该租户的超级管理员**（否则新租户无人可登录）

#### 5.8.3 编辑租户
- **方法与路径**：`PUT /api/v1/tenants/{tenantId}`
- **要点**：可改 `name` / `expiresAt`；**`code` 不可改**（登录凭据，改了会锁死用户）

#### 5.8.4 启用 / 停用租户
- **方法与路径**：`PATCH /api/v1/tenants/{tenantId}/status`
- **用途**：`{ status: ACTIVE | SUSPENDED }`
- **要点**：停用后该租户**登录与 MCP 调用全部拒绝**（数据保留）；**默认租户不可停用**（`40300`）

### 5.9 用户（阶段 1）

#### 5.9.1 用户列表
- **方法与路径**：`GET /api/v1/users`
- **入口**：用户管理页
- **要点**：**仅 ADMIN / 超级管理员可见**（普通用户 `40300`）；分页 A 形状；支持 `keyword` / `role` / `status` 筛选；租户条件由登录态注入，前端不传 `tenantId`

#### 5.9.2 新建用户
- **方法与路径**：`POST /api/v1/users`
- **用途**：`{ username, displayName, role, email?, password? }`
- **要点**：`role` 只允许 `ADMIN` / `USER`（**`SUPER_ADMIN` 由租户初始化产生，`ROOT` 不可创建**）；`username` 租户内唯一 → `40002`（存在性冲突，C2 定案）

#### 5.9.3 编辑用户
- **方法与路径**：`PUT /api/v1/users/{userId}`
- **要点**：可改 `displayName` / `email` / `role`；**不能操作 ROOT**（`40300`）；不能把自己降级为 `USER`（防止把自己锁在外面）

#### 5.9.4 启用 / 停用用户
- **方法与路径**：`PATCH /api/v1/users/{userId}/status`
- **要点**：停用后**该用户所有 api-key 立即失效**（MCP 鉴权时校验 `user.status`，不只看 token 状态）

#### 5.9.5 重置密码
- **方法与路径**：`POST /api/v1/users/{userId}/password/reset`
- **要点**：管理员重置为指定密码或系统生成临时密码（**建议生成且只显示一次**）；SSO 用户调用返回 `40003`；✅ **2026-10-16 拍板（A 类 #1）：重置成功后必须置 `must_change_password = 1`** ⇒ 该用户下次登录拿到 `mustChangePassword: true`，**改密前只能访问白名单接口**（见 §4.1 配套 3）

### 5.10 变更申请（审批，阶段 2）

> 前提：租户配置 `access.change_mode = APPROVAL`（`SIMPLE` 时这些接口对普通用户一律 `40300`，管理员仍可直接改）。

#### 5.10.1 提交申请
- **方法与路径**：`POST /api/v1/change-requests`
- **入口**：「提交审批」按钮（工具 / 服务 / 提示词 / 资源的保存、删除处）
- **用途**：`{ targetType, action, targetId?, parentServiceId?, baseVersion?, draft }`
- **要点**：三条不变量都在这里拦 —— **R2** 同目标已有进行中申请 → `40002`（存在性冲突，C2 定案；附"卡在哪张申请单"）；**R3** 父对象（server）有进行中申请 → 子对象提交 `40002`（同上）；**R5** `baseVersion` 与当前对象 `version` 不一致 → `40901`（"数据已变化，请刷新后重提"）
- **对应设计图**：无（新增模块）

#### 5.10.2 申请列表（审批中心）
- **方法与路径**：`GET /api/v1/change-requests`
- **入口**：审批中心（管理员）
- **要点**：默认 `status=PENDING`；支持 `targetType` / `action` / 申请人筛选；分页 A 形状

#### 5.10.3 我的申请
- **方法与路径**：`GET /api/v1/change-requests/mine`
- **入口**：我的申请页
- **要点**：含 `PENDING` 与历史；**草稿箱（未提交）不在此接口**，属前端本地存储（R4）

#### 5.10.4 申请详情（对比用）
- **方法与路径**：`GET /api/v1/change-requests/{requestId}`
- **要点**：同时返回**申请草稿**与**目标对象当前值**，供前端做 diff 展示；已删除对象返回 `draft` + 标记"目标已不存在"
- **⚠️ 敏感值处理（✅ A4 定案 2026-10-15）**：`draft` 与"目标当前值"里的敏感字段（清单见 **3.2**）**对所有人一律掩码为 `***`，包括审批人本人**。
  - **理由**：审批人的职责是判断"这个改动合不合理"，**不是保管密钥**；把明文摊给每个有审批权的人，等于把凭据可见面从"服务维护者"扩大到"全部管理员"。
  - **替代验证方式**：要确认 token 是否有效，用**「测试」按钮真实发一次请求**（A19）—— 比"看明文"更可靠，且不需要暴露值。
  - **前端差异展示**：敏感字段只显示"已修改 / 未修改 / 已清空"三态，**不显示新旧值**。

#### 5.10.5 批准
- **方法与路径**：`POST /api/v1/change-requests/{requestId}/approve`
- **要点**：**批准时再校验一次 `baseVersion`**（R5，防止管理员直改后照旧结构落库）；**单事务**内：写对象（`CREATE` 建新 / `UPDATE` 整量替换并 `version+1` / `DELETE` 软删除）+ 更新申请单 + 写操作日志 + 发通知；`body: { comment? }`
- **⚠️ 并发闸门（✅ B1 定案 2026-10-15）**：**两个审批人同时点批准，只能有一个成功** —— 用 **CAS 条件更新**：
  ```sql
  UPDATE mcp_change_request
     SET status='APPROVED', applied_at=?, applied_object_id=?
   WHERE id=? AND status='PENDING'
  ```
  **影响行数 = 0** → 说明这张单子已被他人批准/驳回 → 回 **`40901`**（并发冲突），**不写对象、不发通知**。**不用** `SELECT … FOR UPDATE`（持锁久、有死锁面）；MySQL 与 PG 条件更新语义同构。

#### 5.10.6 驳回
- **方法与路径**：`POST /api/v1/change-requests/{requestId}/reject`
- **要点**：`comment` **必填**（要求写原因）；状态 → `REJECTED`；通知申请人

#### 5.10.7 撤回
- **方法与路径**：`POST /api/v1/change-requests/{requestId}/withdraw`
- **要点**：**仅申请人本人**、且必须是 `PENDING`；撤回后该目标的 `dedup_key` 释放，可重新提交

### 5.13 访问管理（api-key，阶段 1）

#### 5.13.1 api-key 列表
- **方法与路径**：`GET /api/v1/access/api-keys`
- **入口**：访问管理页 / 「我的 api-key」
- **要点**：**普通用户只看自己的**；管理员加 `?scope=tenant` 看本租户全部；**列表只返回 `tokenPrefix`，永不返回明文**

#### 5.13.2 生成 api-key
- **方法与路径**：`POST /api/v1/access/api-keys`
- **用途**：`{ name, description?, expiresAt?, neverExpires? }` → 返回 **明文 token（仅此一次）** + 记录信息
- 🔴 **有效期规则（✅ 2026-10-16 主人拍板 —— 修掉一个 fail-open）**：**省略 `expiresAt` 且 `neverExpires != true` → 服务端写 `now() + 90 天`**（安全默认）；**要"永不过期"必须显式传 `neverExpires=true`** → `expires_at = NULL`，且**前端必须醒目警告**（"该凭据永不过期，泄露后无法自动失效"）+ **写审计日志**；`expiresAt` 与 `neverExpires=true` **同时给 → `40001`**。**根因**：表注释「NULL = 永不过期」＋ `expiresAt?` 可选 ⇒ **忘填 = 静默拿到永久凭据**（通则见 [`数据库设计.md`](./数据库设计.md) **§12.4「缺省即最严」**）
- **要点**：**点一下就生成，无需审批**；服务端只存 **SHA-256 哈希 + 前缀**；前端必须提示"**明文只显示这一次，请立即保存**"
- **对应设计图**：无（新增模块）

#### 5.13.3 启用 / 禁用 api-key
- **方法与路径**：`PATCH /api/v1/access/api-keys/{keyId}/status`
- **要点**：`{ status: ACTIVE | DISABLED }`；禁用后 MCP 调用立即 `40100`

#### 5.13.4 删除 api-key
- **方法与路径**：`DELETE /api/v1/access/api-keys/{keyId}`
- **要点**：软删除 + **立即失效**；普通用户只能删自己的（否则 `40300`）

#### 5.13.5 设置可见范围
- **方法与路径**：`PUT /api/v1/access/api-keys/{keyId}/services`
- **用途**：`{ scopeMode: ALL | WHITELIST, serviceIds: [] }`
- **要点**：⚠️ `WHITELIST` 且 `serviceIds` 为空 = **该 key 看不到任何服务**，前端必须明确提示；`serviceIds` 必须属于**同一租户**（跨租户 → `40003`）

## 6. 关键流程

### 6.1 导入会话（4 步 ↔ 3 接口）

```
步骤① 上传        POST   /services/{sid}/imports                     → 会话标识 + 候选清单
步骤② 检查接口信息  （无请求）前端本地：改名 / 改路径 / 反选 / 删除 / 解除
步骤③ 执行导入     POST   /services/{sid}/imports/{iid}/commit        → 结果统计
步骤④ 导入结果     同上接口返回，前端展示
兜底               DELETE /services/{sid}/imports/{iid}（best-effort）+ 服务端 TTL 30 分钟
```

要点：步骤② 全前端 ⇒ commit 收变更集；冲突最终以服务端校验为准；commit 幂等。

### 6.2 标签「统一改名」合并

```
选中多个不同名标签 + 输入新名字 → POST /tags/rename
  ├─ 新名字不存在        → 保留其中 1 个改名为新名字，其余并入并回收
  └─ 新名字已存在（未选中）→ 全部并入该已有标签
返回：合并后的标签 / 是否新建 / 被并入的标签 / 受影响服务数
```

### 6.3 curl 预览实时策略

```
用户编辑 → 是否影响 curl？
  ├─ 否（名称、描述）    → 不请求
  └─ 是 → 离散操作立即发 / 连续输入防抖 200–250ms
        → POST /tools/curl-preview（带自增序号）
        → 只采纳最新序号结果，AbortController 取消在飞旧请求
```

### 6.4 批量操作

服务批量 4 个动作统一 `POST /services/batch/{动作}` + id 集合；工具批量 2 个动作同理。所有批量接口需支持部分成功的结果反馈。

### 6.5 实时能力的升级路径

当前不引入 WS/SSE。触发条件（满足任一即升级到 WS，不走 SSE，因为该场景是双向高频小消息）：① 实测 curl 预览出现可感知延迟；② 参数行连续拖拽需逐帧更新；③ 未来引入多人协同编辑。SSE 不适用：它只能服务端推送，客户端发草稿仍需另开 POST 通道，等于两条链路换一个结果。
