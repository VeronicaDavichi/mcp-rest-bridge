## 1. 设计图还剩什么

### 1.1 ✅ 已关闭：服务级鉴权**天然必填**（0 处要改）

**服务级「鉴权方式」参数表** —— 我在 PSD 里只数到 4 列：

```
类型 | 原参数名 | MCP 参数名 | MCP 对该参数的描述 / 固定值      （+ 行末 −）
```

但定案**曾经**是「四态」（`required` / `nonEmpty` / `value` / `overridable`）—— 我据此以为服务级也缺两列。

**✅ 主人 2026-10-21 已答：「没有，就是天然没设计 —— 必须填，没值算个p的鉴权」** ⇒

| 结论 | 说明 |
| --- | --- |
| **服务级鉴权天然必填** | `required` **恒 `1`** ⇒ **UI 不要这两列**（不是漏画，是**不需要**）；语义是「**最终值必须存在**」（写死或调用方传，二选一）。🔄 **2026-10-21 晚：`nonEmpty` 恒 `0`** —— **允许空串**（决策 **#27**） |
| **`允许调用方覆盖` 已废除** | `overridable` 降级为**派生列**（`= value IS NULL`）—— "给默认值 + 允许覆盖"的组合**不存在** |
| **描述与固定值同格互斥** | 「动态」选中 → 填**描述**（给模型看）；不选 → 填**固定值**（凭据，不进 `inputSchema`） |
| **现有 4 列 + 切换即完整** | `类型 / 原参数名 / MCP 参数名 / 描述或固定值` ⇒ **设计图 0 处要改，本清单彻底收工** 🎉 |

## 2. 不进设计图的 14 项（✅ 主人 2026-10-21 拍定）

> 这一节**每一条都是"图上不画，靠校验 / 报错兜住"**。前端照此实现即可，设计图不需要体现。

| # | 项 | 归属 | 规则 / 文案 |
| --- | --- | --- | --- |
| **1** | **服务名唯一** | 后端保存校验 | 撞 `uk_service_name (tenant_id, name_norm, deleted_seq)` → **`40002`**「服务名已存在」；**图不画实时校验** |
| **2** | **工具名格式** | 后端保存校验 | `^[A-Za-z0-9_\-.]+$`、长度 **1~128**；中文 / 空格 / 斜杠 → **`40001`** + `data.errors[]`「工具名只允许字母、数字、`_`、`-`、`.`，长度 1~128」**（中文会被拒）** |
| **3** | **简称长度** | 后端保存校验 | **≤ 8 个半角单位**（1 个 ASCII = 1；**1 个非 ASCII / 全角 = 2**）⇒ 8 英文满、4 汉字满；超限 **`40001`**。图上文案够用，**措辞以本条为准** |
| **4** | **URL 前缀** | 后端保存校验 | 仅 `http` / `https`；必须**绝对 URL**；**末尾 `/` 自动归一**（防拼出 `//`）；不合规 → **`40001`**「URL 前缀需以 `http(s)://` 开头」 |
| **5** | **导入文件格式** | 后端解析报错 | 🔴 **扩展名与版本解耦**：`.json` / `.yaml` / `.yml` **都收**，版本**按内容探测**（OpenAPI 3.0 / 3.1 / Swagger 2.0）；识别不了 → **`40001`**「无法识别为 OpenAPI 3.x / Swagger 2.0」。⚠️ 图上那句「Json↔OpenAPI3、Yaml↔Swagger2」的绑定文案**不改也能跑**，靠这条报错兜底 |
| **6** | **导入文件大小** | 后端校验 | **> 10 MB** → `40001`「文件超过 10MB」；扩展名不在 `.json/.yaml/.yml` → `40001`「仅支持 `.json` / `.yaml` / `.yml`」 |
| **7** | **测试路径失败态** | 后端 + 前端按响应渲染 | 图上只有成功态 `204 No Content`；**失败态由前端渲染**（红字 + 状态码 + 耗时）：超时 **5s** / DNS 失败 / 连接拒绝 / 401 / 5xx / 非 HTTP 响应 |
| **8** | **测试路径的输入** | 前端交互 | 「GET 测试路径」那一行 = **输入框 + 发送按钮**（位置不动，补样式即可）；后端入参 = **URL 前缀 + 测试路径 + 鉴权映射**（**草稿态可测**，见 `前后端交互接口设计.md` **§5.2.8**） |
| **9** | ~~`必填` × `固定值` 互斥~~ → **服务级天然必填** | 规则（2026-10-21 改判） | **服务级鉴权**：`required` **恒 `1`**、`nonEmpty` **恒 `0`**（**允许空串**，#27），不暴露开关 ⇒ **没有互斥问题**。**工具级参数**：`value` 非空 ⇒ `required` **必须为 `0`**（矛盾组合 → `40001`） |
| **10** | **「删除 ×」显隐** | 前端交互 | **新建态隐藏 / 禁用**；**编辑态才显示**（新建时没有可删的东西） |
| **11** | **术语统一** | 文档 | 统一叫「**工具**」。服务页「新增接口」的实际语义 = **先保存服务 → 跳转新建工具**（文案改成「新增工具」更好，**不改也能跑**，按本表口径实现） |
| **12** | **副标题「编辑的时候写作编辑服务」** | 文档 | 那是**给设计的注释**，**上线不渲染**；已登记进视觉走查清单 |
| **13** | **`动态` 的语义**（✅ 最终定案） | 文档 | 🔄 **2026-10-21 改判：`overridable` 不是独立开关，恒等于 `(value IS NULL)`** —— **选中「动态」→ 该格填"描述"**（值由调用方传，需给模型解释）；**不选（= 固定）→ 填"固定值"**（凭据，不进 `inputSchema`）。**二者互斥，"默认值 + 可覆盖"的组合不存在** ⇒ **我上一轮说的"唯一例外"已作废**（主人原话：「参数描述和固定值占同一个字段，不存在覆盖一说」） |
| **14** | **两行表头不一致** | ✅ 撤回 | 你说明了**有切换按钮**（我上轮没认出来），**不是问题** |

## 3. 已拍定的交互行为（进接口文档）

| 行为 | 定案（2026-10-21） |
| --- | --- |
| **「导入接口」/「新增接口」点击** | 🔴 **先保存（`POST /services` 或 `PUT /services/{id}`）→ 成功后再跳转**。服务未保存时点它们 = **自动触发保存**；保存失败则**不跳转**，停在原页显示 `40001` / `40002` 错误 |

> 这条也解释了为什么两个按钮在**新建页**上就能点：**它们自带"隐式保存"**。
